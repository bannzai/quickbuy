# 購入画面の URL は決まった形で組み立てる

購入画面を開く URL と、購入の流れに触れるコードを書く時に従う。決定と理由は [ADR 0003](../../documents/adr/0003-open-purchase-screen-by-fixed-url-and-user-confirms-payment.md)。

- 購入を完了させる処理を書かない。アプリが行うのは購入画面を開くところまで (ADR 0003)
- EC サイトのログイン情報を保存・送信する処理と、ログイン済みの画面を自動で操作する処理を書かない (ADR 0003)
- 外から渡された URL をそのまま開かない。店のドメイン・商品の識別子・個数に分解し、形式ごとの組み立ての関数 (Shopify の店のカートに足す URL は `Shared/ShopifyCartAdd.swift`、Amazon の商品ページは `Shared/AmazonProductPage.swift`) で組み立て直す (ADR 0003)
- 組み立ての関数は店のドメインの形だけを検査し、どの店かは見ない。店のドメインは、お気に入りの登録の画面で利用者に見せて確かめてもらったものだけを保存し、購入画面は保存済みのお気に入りからだけ開く。外から渡されたリンクから、確認の画面を通さずに保存する処理・開く処理を書かない (ADR 0003)
- URL の形式を足す時は、形式ごとに組み立ての関数を 1 つ置き、通す入力と通さない入力の両側のテストを書く。形式の出典 (公式ドキュメントの URL、公式ドキュメントが無い形式は実際に開いて確かめた日付と結果) を関数の document コメントに書く
- 提供元が本人以外への共有とログへの記録を禁じている決済の URL を、通知・ログ・計測のイベントに載せない (ADR 0003)
