# Quick Buy の要件

Shopify の店と Amazon で「同じものをまた買う」ための、再購入のショートカットアプリ。ホーム画面のウィジェットをタップすると、いつもの商品がカートに入った状態の購入画面が開く。支払いの確定は毎回、本人が行う。

企画の全文: https://github.com/bannzai/IdeaMemo/issues/398
判断の根拠 (仮説・判定基準・必要な機能・決めたこと・用語): [DIRECTION.md](DIRECTION.md)

## 対象にする人

- 同じ商品を定期的に買いたい
- 定期便や AI による自動購入には、購入の時に不安がある。買う時は自分で決めたい
- それでも、毎回店を開いて商品を探してカートに入れる手間は省きたい

## 体験の流れ

1. アプリのトップページで商品を検索し、種類と個数を選んでお気に入りにする
2. お気に入りの一覧で「カートイン」を押し、「購入画面を開きますか？」の確認に答えると、その商品がカートに入った状態の購入画面が開く
3. お気に入りはホーム画面のウィジェットにも並ぶ。ウィジェットの「カートイン」を押すと同じ確認が通知で届き、通知をタップすると購入画面が開く
4. 本人が店の画面で支払いを確定する
5. お気に入りごとに「何日ごとに知らせるか」を設定しておくと、その日数が過ぎた時に通知が届き、通知からも購入画面を開ける (リマインド)

## プラットフォーム

- iOS: Swift (SwiftUI・WidgetKit・App Intents)。iOS 17 以降
- Android: Kotlin (Glance)。iOS の最初の版の後に着手する

## 作る順

企画の「最初に作る範囲」に沿う。機能の一覧は DIRECTION.md の「必要な機能」が正。

1. iOS で、検索 → お気に入り → カートイン (アプリとウィジェット) → 購入画面、の流れを通す (お気に入りは端末内に保存する。[ADR 0001](adr/0001-device-local-storage-and-no-backend-for-first-version.md))
2. 自分のサーバーを経由する URL を足す
3. 相性の良い商品の一覧・店向けの無料 Shopify アプリを足す
4. Android 版を作る

## 守ること

- アプリは購入を完了させない。EC サイトのログイン情報を預からない。購入画面の URL は決まった形で組み立てる ([ADR 0003](adr/0003-open-purchase-screen-by-fixed-url-and-user-confirms-payment.md))
- 消費者向けアプリは無料
- 連絡先のメールアドレスは bannzai.app@gmail.com

## 外部サービスの規約で設計に効くもの

調査の全文と出典は [research/2026-11-17/](research/2026-11-17/) にある (2026-11-17 時点)。実装の前に該当のファイルを読む。下は要約で、規約の原文と、調査した agent の読み (提供元に確かめていない解釈) の区別は各ファイルに書いてある。

- **Amazon アソシエイト** (`monetization.md`): アプリにリンクを置くには Amazon の審査での承認が要る。承認の条件に「Amazon のショッピングアプリの機能を模倣しない」「WebView で Amazon のページを表示しない」がある。運営者本人と近しい人がリンク経由で買うこと、利用者のクリック無しで Amazon へ送るリンク、印刷物 (QR を含む) での利用、価格の追跡・アラートは規約で禁じられている
- **Shopify の cart permalink** (`feasibility.md`): 従来の `/cart/{商品バリアントの ID}:{個数}` は legacy。後継の `/buy` は、店の `/.well-known/ucp` から endpoint を読む、開くと既存のカートを置き換える、定期購入が必須の商品は入らない
- **Shopify の決済の URL** (`feasibility.md`): Checkout MCP の `continue_url` は本人以外に共有せず、ログに残さない
- **iOS のウィジェット** (`feasibility.md`): タップで渡る URL は自分のアプリが受け取る。ウィジェットから Safari を直接開けるかは実機で未確認
