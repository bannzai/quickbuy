# Quick Buy の要件

Shopify の店と Amazon で「同じものをまた買う」ための、再購入のショートカットアプリ。アプリの一覧かホーム画面のウィジェットで「カートイン」を押して確認に答えると、いつもの商品がカートに入った状態の購入画面が開く。支払いの確定は毎回、本人が行う。

企画の全文: https://github.com/bannzai/IdeaMemo/issues/398
判断の根拠 (仮説・判定基準・必要な機能・決めたこと・用語): [DIRECTION.md](DIRECTION.md)

## 対象にする人

- 同じ商品を定期的に買いたい
- 定期便や AI による自動購入には、購入の時に不安がある。買う時は自分で決めたい
- それでも、毎回店を開いて商品を探してカートに入れる手間は省きたい

## 体験の流れ

1. アプリのトップページで商品を検索し、種類と個数を選んでお気に入りにする
2. お気に入りの一覧で「カートイン」を押し、「購入画面を開きますか？」の確認に答えると、その商品がカートに入った状態の購入画面が開く
3. お気に入りはホーム画面のウィジェットにも並ぶ。ウィジェットの「カートイン」を押すと同じ確認が通知で届き、通知をタップすると購入画面が開く
   - Shopify の店では、開くたびにその店のカートへ商品が個数分足される。同じ店のお気に入りを続けてカートインすると、前に足した物の入ったカートに足されていき、店の画面で 1 回の支払いにできる
4. 本人が店の画面で支払いを確定する
5. お気に入りごとに「何日ごとに知らせるか」を設定しておくと、その日数が過ぎた時に通知が届き、通知からも購入画面を開ける (リマインド)

## プラットフォーム

- iOS: Swift (SwiftUI・WidgetKit・App Intents)。iOS 17 以降
- Android: Kotlin (Glance)。iOS の最初の版の後に着手する

## 作る順

企画の「最初に作る範囲」に沿う。機能の一覧は DIRECTION.md の「必要な機能」が正。

1. iOS で、検索 → お気に入り → カートイン (アプリとウィジェット) → 購入画面、の流れを通す (お気に入りは端末内に保存する。[ADR 0001](adr/0001-device-local-storage-and-no-backend-for-first-version.md))
2. 自分のサーバーを経由する URL を足す
3. 相性の良い商品の一覧・店向けの無料 Shopify アプリを足す
4. Android 版を作る

## 守ること

- アプリは購入を完了させない。EC サイトのログイン情報を預からない。購入画面の URL は決まった形で組み立てる ([ADR 0003](adr/0003-open-purchase-screen-by-fixed-url-and-user-confirms-payment.md))
- 消費者向けアプリは無料
- 連絡先のメールアドレスは bannzai.app@gmail.com

## 外部サービスの規約で設計に効くもの

調査の全文と出典は [research/2026-11-17/](research/2026-11-17/) (2026-11-17 時点) と [research/2026-11-18/](research/2026-11-18/) (2026-11-18 時点。商品の検索の API と Amazon で開く URL) にある。実装の前に該当のファイルを読む。下は要約で、規約の原文と、調査した agent の読み (提供元に確かめていない解釈) の区別は各ファイルに書いてある。

- **Amazon アソシエイト** (`monetization.md`): アプリにリンクを置くには Amazon の審査での承認が要る。承認の条件に「Amazon のショッピングアプリの機能を模倣しない」「WebView で Amazon のページを表示しない」がある。運営者本人と近しい人がリンク経由で買うこと、利用者のクリック無しで Amazon へ送るリンク、印刷物 (QR を含む) での利用、価格の追跡・アラートは規約で禁じられている
- **Shopify の購入画面の URL** (`feasibility.md`): アプリは `/cart/add?id={商品バリアントの ID}&quantity={個数}` を開き、店のカートに足していく (2026-11-26 に実在の店で、続けて開くと前の物が残ったまま足されることを確かめた。結果は `Shared/ShopifyCartAdd.swift` の document コメント)。GET の `/cart/add` を説明する公式の文書は見つかっていない。cart permalink の `/cart/{商品バリアントの ID}:{個数}` は legacy で、開くたびに押した物だけの新しい購入画面になる。後継の `/buy` は、店の `/.well-known/ucp` から endpoint を読む、開くと既存のカートを置き換える、定期購入が必須の商品は入らない
- **Shopify の決済の URL** (`feasibility.md`): Checkout MCP の `continue_url` は本人以外に共有せず、ログに残さない
- **iOS のウィジェット** (`feasibility.md`): タップで渡る URL は自分のアプリが受け取る。ウィジェットから Safari を直接開けるかは実機で未確認
- **Shopify の Catalog** (`research/2026-11-18/search-api-and-amazon-purchase-url.md`): 商品の検索に使う。鍵なしで呼べるが、Shopify は Global Catalog の鍵なしの呼び出しを本番に使わないよう書いており、上限を上げられない。返った名前と画像は 24 時間、価格は 10 分を超えて持たない。client secret はアプリに埋め込まない
- **Amazon の Creators API とリンク** (同じファイル): 検索の API は、Amazon が承認したモバイルアプリ・過去 30 日に 10 件の適格販売・鍵を置く自分のサーバーが要る。アプリは Amazon が返した名前・画像・価格を保存もキャッシュもできない (ASIN は保存できる)。承認の前のアプリのリンクにアソシエイトの ID を付けない。Amazon のリンクはアプリの外で開く。最初の版は商品ページを開き、開いた時に商品はカートに入っていない
