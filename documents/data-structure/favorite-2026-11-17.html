最初の版 (iOS で お気に入り → ウィジェットのタップ → 購入画面) が端末内に保存するデータの案。実装の前に見てもらうための資料で、まだコードには入れていない (2026-11-17 作成。同日に bannzai の判断を反映して改訂)。

改訂で変えた点 (2026-11-17 の bannzai の判断)

  • 商品バリアントの ID を文字列にした
  • Product の各 case に、struct で定義した型 (ShopifyProduct・AmazonProduct) を持たせた
  • 「いつものセット」を無くした (同じ店の商品を 1 つの URL にまとめる操作も無くした)
  • リマインド (設定した日数ごとの通知) を足した。型と動きは agent の案で、下の「見てほしい点」に書いた

型定義 (Swift)

/// お気に入り: 利用者が「また買う」ために登録した 1 つの商品。
struct Favorite: Codable, Identifiable, Equatable {
    /// お気に入りの識別子 (端末内で作る)。
    let id: UUID
    /// 一覧とウィジェットに出す名前。利用者が編集できる。
    var name: String
    /// 商品バリアントの名前 (例: 200g / 豆のまま)。同じ商品の商品バリアントごとのお気に入りを見分けるために出す。
    /// 商品バリアントが 1 つだけの商品と、商品バリアントの名前を取っていない商品 (Amazon の商品) では nil。
    var variantName: String?
    /// 商品の画像の URL。取得できなかった時は nil。
    var imageURL: URL?
    /// 1 回に買う個数。1 以上。
    var quantity: Int
    /// どの店のどの商品か。
    var product: Product
    /// リマインド。設定していなければ nil。
    var reminder: Reminder?

    /// 購入画面を開くのに要る、店の種類ごとの商品の指し方。
    enum Product: Codable, Equatable {
        case shopify(ShopifyProduct)
        case amazon(AmazonProduct)
    }
}

/// Shopify の店の商品。
struct ShopifyProduct: Codable, Equatable {
    /// 店のドメイン (例: example.myshopify.com)。
    var shopDomain: String
    /// 商品バリアントの ID。数字だけの文字列。
    var variantID: String
}

/// Amazon (amazon.co.jp) の商品。
struct AmazonProduct: Codable, Equatable {
    /// ASIN。
    var asin: String
}

/// リマインド: 設定した日数ごとに、買う頃だと通知する設定。
struct Reminder: Codable, Equatable {
    /// 何日ごとに知らせるか。1 以上。
    var intervalDays: Int
    /// 日数を数え始めた日時。リマインドを設定した時と購入画面を開いた時に、その時刻へ更新する。通知はこの日時から intervalDays 日ごとに出す。
    var countedFrom: Date
}

/// 端末内 (アプリとウィジェットが共有する領域) に保存するのは [Favorite] の 1 つだけ。
/// 配列の並びが、一覧とウィジェットの並び順になる。
  • 購入画面の URL は保存しない。開く時に、店のドメイン・商品の識別子・個数から決まった形で組み立てる (Shopify は https://{店のドメイン}/cart/{商品バリアントの ID}:{個数})
  • 商品バリアントの ID は文字列で持つため、URL を組み立てる時に数字だけであることを検査する (数字以外を含む ID は URL に入れない)
  • アカウント・サーバーに置くデータ・購入の履歴は持たない
  • 通知は端末の中だけで予約する (サーバーから送らない)
  • 予約する通知は、お気に入り 1 件につき 1 つにする。countedFrom か intervalDays を書き換える時は、前の予約を取り消してから予約し直す
  • 数え直しは、タップがアプリを通る前提で成り立つ。ウィジェットのタップがアプリを通らずに店の画面を開く作りになる場合は countedFrom を更新できないため、ウィジェットを実装する時に実機で確かめる (未確認)

利用者の操作と、読み書きするデータ

利用者の操作アプリがすること読み書きするデータ
商品ページの URL か、店が配る追加リンクを、貼り付けるか共有メニューから Quick Buy に渡す URL から店のドメインと商品の識別子を取り出す。取り出せない URL は登録しない まだ書かない
名前を確かめ、種類 (商品バリアント) を選んでそれぞれの個数を決め、「お気に入りに追加」を押す 選んだ商品バリアントごとに、お気に入りを 1 件ずつ足す (商品バリアントが 1 つだけの商品は 1 件) 書く Favorite (id・name・variantName・imageURL・quantity・product)
アプリを開いてお気に入りの一覧を見る 保存した並びのまま表示する 読む [Favorite]
名前・個数を変える、並べ替える、削除する 変えた内容で保存し直し、ウィジェットを更新する。削除した時は、そのお気に入りの予約済みの通知を取り消す 書く name・quantity・配列の並び・要素の削除
お気に入りに「何日ごとに知らせるか」を設定する (変える・やめる) そのお気に入りの予約済みの通知を取り消してから、設定した時刻から日数分あとに通知を予約する。やめた時は予約を取り消すだけにする 書く reminder (intervalDays・countedFrom)。やめた時は nil
ホーム画面にウィジェットを置く 並びの先頭から、ウィジェットの大きさに入る数だけ表示する 読む [Favorite]
ウィジェットか一覧で商品をタップする その商品が個数分カートに入った購入画面の URL を組み立てて開く。リマインドがあれば、予約済みの通知を取り消し、開いた時刻から日数分あとに予約し直す 読む Favorite 1 件 (product・quantity)
書く リマインドがあれば countedFrom (開いた時刻から数え直す)
リマインドの通知を受け取り、タップする その商品の購入画面を開く (ウィジェットのタップと同じ動きで、通知も予約し直す)。通知が指すお気に入りが無い時は、購入画面を開かずお気に入りの一覧を表示する 読む Favorite 1 件 (product・quantity)
書く countedFrom (開いた時刻から数え直す)
通知を受け取ったが、タップしない 何もしない。同じ日数が過ぎたら、もう一度知らせる 読み書きしない
店の画面で内容を確かめ、支払いを確定する 何もしない (店の画面での操作) 読み書きしない

見てほしい点

1. URL ではなく、店のドメイン・商品の識別子・個数を保存する

企画は「cart permalink と Amazon のカートに入れる URL を保存して開く形」だった。URL のまま保存すると、個数を変えるたびに URL を書き換えることになり、渡された URL をそのまま開く作りにもなる。そのため部品で保存する案にした。

2. リマインドの数え方 (agent の案)

「何日ごと」を、購入画面を開いた時刻から数える案にした。Quick Buy は購入が完了したかを知れないため、開いた時を「買った時」の代わりにする。開いただけで買わなかった時も数え直しになる。通知を無視した時は、同じ日数でもう一度知らせる。

3. 通知をタップした時の動き (agent の案)

お気に入りの一覧ではなく、その商品の購入画面を直接開く案にした。「決めた後は 1 タップ」に合わせるため。

4. 同じ店の商品を続けて開いた時に、2 つともカートに入るかは未確認

「いつものセット」を無くしたので、同じ店の 2 商品を買う時は 2 回タップすることになる。Shopify の後継の形式 (/buy) の文書には「The new cart replaces any cart that the buyer already had on the store.」とあり、開くたびにカートが置き換わる。最初の版で使う従来の形式 (/cart/{ID}:{個数}) は、文書に記載が無く確かめられていない。置き換わる場合、1 つ目の支払いを済ませてから 2 つ目を開く使い方になる。実装の時に実際の店で確かめる。

5. 最初の版の追加の入口は「URL を貼り付ける・共有メニューから渡す」

企画の入口 (アプリ内の検索・相性の良い商品の一覧・店が配るリンクや QR) のうち、検索と一覧は Shopify の Catalog の API キーと自分のサーバーが要る。それらが無い最初の版で登録できるように、この入口を足した。
