最初の版 (iOS で お気に入り → ウィジェットのタップ → 購入画面) が端末内に保存するデータの案。保存する型はこの 1 つだけ。実装の前に見てもらうための資料で、まだコードには入れていない (2026-11-17 作成)。

型定義 (Swift)

/// お気に入り: 利用者が「また買う」ために登録した 1 つの商品。
struct Favorite: Codable, Identifiable, Equatable {
    /// お気に入りの識別子 (端末内で作る)。
    let id: UUID
    /// 一覧とウィジェットに出す名前。利用者が編集できる。
    var name: String
    /// 商品の画像の URL。取得できなかった時は nil。
    var imageURL: URL?
    /// 1 回に買う個数。1 以上。
    var quantity: Int
    /// どの店のどの商品か。
    var product: Product

    /// 購入画面を開くのに要る、店の種類ごとの商品の指し方。
    enum Product: Codable, Equatable {
        /// Shopify の店の商品。店のドメインと商品バリアントの ID。
        case shopify(shopDomain: String, variantID: UInt64)
        /// Amazon (amazon.co.jp) の商品。ASIN。
        case amazon(asin: String)
    }
}

/// 端末内 (アプリとウィジェットが共有する領域) に保存するのは [Favorite] の 1 つだけ。
/// 配列の並びが、一覧とウィジェットの並び順になる。
  • 購入画面の URL は保存しない。開く時に、店のドメイン・商品の識別子・個数から決まった形で組み立てる (Shopify は https://{店のドメイン}/cart/{商品バリアントの ID}:{個数})
  • 店ごとの「いつものセット」は保存しない。同じ店のお気に入りを、開く時に 1 つの URL にまとめる
  • アカウント・サーバーに置くデータ・購入の履歴・最後に開いた日時は持たない

利用者の操作と、読み書きするデータ

利用者の操作アプリがすること読み書きするデータ
商品ページの URL か、店が配る追加リンクを、貼り付けるか共有メニューから Quick Buy に渡す URL から店のドメインと商品の識別子を取り出す。取り出せない URL は登録しない まだ書かない
名前と個数を確かめて「お気に入りに入れる」を押す お気に入りを 1 件足す 書く Favorite (id・name・imageURL・quantity・product)
アプリを開いてお気に入りの一覧を見る 保存した並びのまま表示する 読む [Favorite]
名前・個数を変える、並べ替える、削除する 変えた内容で保存し直し、ウィジェットを更新する 書く name・quantity・配列の並び・要素の削除
ホーム画面にウィジェットを置く 並びの先頭から、ウィジェットの大きさに入る数だけ表示する 読む [Favorite]
ウィジェットか一覧で商品をタップする その商品が個数分カートに入った購入画面の URL を組み立てて開く 読む Favorite 1 件 (product・quantity)
同じ店のお気に入りをまとめて開く (いつものセット) 同じ店のお気に入りを 1 つの URL にまとめて開く 読む product が同じ shopDomain の Favorite
店の画面で内容を確かめ、支払いを確定する 何もしない (店の画面での操作) 読み書きしない

見てほしい点

1. URL ではなく、店のドメイン・商品の識別子・個数を保存する

企画は「cart permalink と Amazon のカートに入れる URL を保存して開く形」だった。URL のまま保存すると、個数の変更と、同じ店の商品をまとめることのたびに URL を書き換えることになり、渡された URL をそのまま開く作りにもなる。そのため部品で保存する案にした。

2. 「いつものセット」を保存しない

この案では、同じ店のお気に入りは全部まとめて 1 つのセットになる。「セットに入れる商品を選ぶ」「セットに名前を付ける」「同じ店でセットを 2 つ持つ」が要るなら、セットを表す型を足す。

3. 最初の版の追加の入口は「URL を貼り付ける・共有メニューから渡す」

企画の入口 (アプリ内の検索・相性の良い商品の一覧・店が配るリンクや QR) のうち、検索と一覧は Shopify の Catalog の API キーと自分のサーバーが要る。それらが無い最初の版で登録できるように、この入口を足した。
