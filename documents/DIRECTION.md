# 方向性: Quick Buy

## 仮説

同じ商品を定期的に買いたいが、定期便や AI による自動購入には、購入の時に不安がある人が、いつもの商品が切れそうな時に、店を開いて商品を探してカートに入れる手間を面倒に感じている。お気に入りにした商品をアプリの一覧とホーム画面のウィジェットに並べ、「カートイン」を押して確認に答えると商品がカートに入った状態の購入画面が開くことで、「自分で決めるが、決めた後は探さずに買える」にする (「カートイン」と確認を挟む流れは 2026-11-18 の bannzai の判断。それに合わせた言い直しは agent)。リマインドが、買うことを思い出すきっかけになる。支払いの確定は毎回本人が行う (出典: https://github.com/bannzai/IdeaMemo/issues/398 、評価レポート `documents/research/2026-11-17/report.md`。対象の人の言い方とリマインドは 2026-11-17 の bannzai の判断)。

## 判定基準

しきい値は実測の裏付けが無い仮の値 (評価レポートの「撤退・継続の基準」と同じ)。計測元の指標は、計測と bannzai/dashboard への収集を入れた後に読めるようになる。

アプリが Firebase Analytics (プロジェクト `quickbuy-app-prod`) に記録するイベントと、計測元の指標への数え方 (https://github.com/bannzai/quickbuy/issues/39 で入れた。bannzai/dashboard への収集はまだ無い):

- `purchase_screen_open`: Shopify の店の購入画面を開いた時に 1 件。引数は `entry_point` (`favorites_list` = 一覧の確認の「開く」、`cart_in_notification` = ウィジェットの「カートイン」の確認の通知のタップ、`reminder_notification` = リマインドの通知のタップ) と `store` (`shopify` = 購入画面)。`purchase_open` の `users` は `store` が `shopify` のこのイベントを記録した利用者の数、`purchase_open_retention` の `d14_rate` は `store` が `shopify` のこのイベントを記録した利用者のうち、次の 14 日にも `store` が `shopify` のこのイベントを記録した人の割合 (`store` は、店の種類を足した時に分けて数えるために残している。最初の公開では Amazon の対応を外したため、値は `shopify` だけ。下の「決めたこと」の 2026-11-27 の行)
- `widget_placed`: アプリが前面に来た時に、お気に入りのウィジェットをホーム画面に置いていれば 1 件。引数は `widget_families` (置いている大きさ `small`・`medium`・`large`・`extra_large_portrait` (iOS 27 以降の縦長の特大サイズ) を名前の順に `,` でつないだ値)。`widget_adoption` の `rate` は、期間の新規の利用者 (Firebase Analytics の自動のイベント `first_open` を記録した利用者) のうち、このイベントを記録した人の割合。ウィジェットを置いた後にアプリを前面に出していない利用者 (ウィジェットと通知だけで使い、通知のタップでも開いていない人) は記録されないため、実際より低く出ることがある
- 両方のイベントに、商品・店・お気に入りの名前、店のドメイン、購入画面の URL は入れない。Debug の設定のビルド (開発中とユニットテスト) は記録を送らない

| --- | --- | --- | --- | --- |
| 直近 14 日に購入画面を 1 回以上開いた利用者数 | `bash ~/.agents/skills/product-loop/scripts/read-dashboard-metric.sh --repo bannzai/quickbuy --metric purchase_open --field users --days 14 --agg sum` の `VALUE` | >= 10 | < 3 x2 (2 回連続) | 新規の利用者は 10 人以上いるのに開いた利用者が 3 人未満なら、お気に入りを登録する入口を作り直す |

## 必要な機能

- [x] トップページ: 通常の EC のように、検索窓と画像つきの商品を並べる (https://github.com/bannzai/quickbuy/issues/34 で作った。並べる物とプロフィールの置き場所は下の「決めたこと」の 2026-11-19 の行)。検索した商品から「お気に入り追加」に進む。検索するのは Shopify の店の商品で、Shopify の Catalog (店をまたぐ検索は Global Catalog `https://catalog.shopify.com/api/ucp/mcp` の `search_catalog`。選んだ商品の種類は、店ごとの入口 `https://{店のドメイン}/api/ucp/mcp` の `get_product` を、種類を選ぶたびに呼び直して取る) を、鍵なしでアプリから直接呼ぶ。最初の版では API キーの発行は要らない。Shopify は Global Catalog の鍵なしの呼び出しを本番に使わないよう書いており (「Don't use unauthenticated requests for production traffic」)、鍵なしでは上限を上げられない。鍵ありにするには鍵を置く自分のサーバーが要るため、サーバーを持たない最初の版は鍵なしにする。自分で置いたプロフィール (`ucp/agent-profile.json`) で通ることは 2026-11-19 に実測した (下の「決めたこと」の 2026-11-19 の行)。人気の順を返す API は Shopify の Catalog の文書に見つからなかったため、検索の前には買い直す物の検索語と決まった検索語の結果を並べる (下の「決めたこと」の 2026-11-19 の行。出典・実測・未確認の点: `documents/research/2026-11-18/search-api-and-amazon-purchase-url.md`)

## デザインの方向

bannzai の返答 (2026-11-18。https://github.com/bannzai/quickbuy/issues/8#issuecomment-6966345862 ): 通常の EC のようなトップページにする。商品の画像を出し、タイトルをのっぺりさせない。トップページに検索窓を置く。

この返答で作り直したモックは `documents/design/mock-2026-11-18/`。bannzai はこのモックの方向でよいと返答した (2026-11-18「良いと思います。」。https://github.com/bannzai/quickbuy/issues/8#issuecomment-6968093230 )。1 つ前の `documents/design/mock-2026-11-17/` は採らない。

画面はこのモックに合わせて作る。色・角の丸み・文字の太さの値はモックの HTML が正で、下はモックから読み取った要点 (bannzai が値を 1 つずつ指定したものではなく、agent がモックに置いた値)。

- 強調の色は緑 (`#0B6E4F`)。「カートイン」「お気に入り追加」などの主なボタンと選択中の印に使う
- 画面の地は薄い灰色 (`#F4F5F7`)、商品や行は白いカードに載せる。文字は濃い色 (`#111318`)、補足の文字は灰色 (`#5B6270`)
- 商品の画像を行とカードの左か上に出す (モックは画像を図形で代えている)
- 見出しと商品の名前は太い文字にし、画面の見出しは大きくする。書体は iOS の標準の書体を使う
- カードとボタンは角を丸くする
- 「そろそろ買う頃」の知らせは、強調の色とは別の色 (`#9A3412`) で出す

## agent に任せること

文書に無い問いはすべて。画面構成・文言・ライブラリの選定・テストの方針を含む。次は任せず、bannzai が決める・行う。

- Amazon アソシエイトのアプリの承認の申請、Shopify・Amazon の商品を検索する API のキーの発行 (外部サービスとの新規の連携)。Firebase のプロジェクトの作成は 2026-11-18 の返答で agent が行う
- 自分のサーバーを持つ時の費用の上限
- 公開に進むか

## 費用

| 項目 | 値 |
| --- | --- |
| 月間売上の取得元 | |
| インフラ費用の取得元 | `echo 0` |
| 固定費の月額上限 (USD) | 0 |

最初の版はサーバーを持たないため、インフラ費用は 0 で、固定費の上限も 0 にしている。サーバーを持つ時に、取得元を費用を取るコマンドへ書き換え、上限を bannzai が決める。

## 用語

| 用語 | 定義 | 使わない言い換え |
| --- | --- | --- |
| お気に入り | 利用者が「また買う」ために登録した 1 つの商品。店・商品・個数を持つ | ブックマーク・ウィッシュリスト・欲しいもの |
| 店 | 商品を売っている Shopify のストア (最初の公開で扱う店。Amazon 等の EC サイトは、扱う時に足す) | ショップ・マーチャント・ストア |
| 購入画面 | 店の側の画面で、商品がカートに入った状態から支払いの確定までを行う画面。Quick Buy が開くのはここまで | チェックアウト・決済画面・カート画面 |
| 商品の詳細ページ | Quick Buy の中の画面で、トップページの商品のカードを押すと開く。Shopify の店の商品の大きい画像・価格・種類の選び方・説明文を見せ、「お気に入り追加」に進める。店の側の商品ページとは別のもの | 商品ページ・商品詳細・詳細画面 |
| リマインド | お気に入りごとに設定した日数が過ぎた時に、買う頃だと端末の通知で知らせること | リマインダー・アラート・定期通知 |
| 追加リンク | 店が配る、その店の商品を Quick Buy のお気に入りに入れるためのリンクや QR | ディープリンク・招待リンク |
| 経由 URL | 自分のサーバーの URL で、開かれた時に店の購入画面へ送るもの。中身の商品を後から変えられる | 短縮 URL・リダイレクト URL |
